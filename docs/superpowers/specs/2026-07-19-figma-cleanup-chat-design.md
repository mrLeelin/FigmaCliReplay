# Figma AI 整理窗口多轮对话

## 目标

将“AI 自动整理节点”从一次性、受限的结构计划生成，改为 Figma 插件窗口内可续接的 AI 对话。AI 仍以 `figma-hierarchy-cleanup-mcp` 为唯一整理技能，并通过该技能规定的本地 Relay 脚本执行读写与验证。

## 交互

1. 点击整理按钮后，窗口读取当前选区并启动 `cleanup` 对话会话；首次回合只允许读取、分析并展示完整最终树，不能写入 Figma。
2. 用户可在“AI 执行”页持续发送反馈；同一个 CLI 会话被恢复，避免每次重新猜测层级。
3. 用户明确确认计划后，AI 按技能执行整理和验证；层级完成后，AI 在同一对话内询问是否满意。
4. 用户确认满意后，AI 执行技能规定的 ComponentSet 阶段；用户提出调整时，AI 重新分析并修订计划。

## 安全与日志

- 首轮任务文件明确限定为只读分析；只有后续会话的明确确认语义才允许技能写入。
- 不允许官方/通用 Figma MCP 直写，保留技能的脚本入口、验证和失败停止规则。
- 每次启动、CLI 拉起、每一条用户续聊、停止和结果都复用会话 `runId` 写入统一日志；记录任务类型、AI 提供方、轮次、输入长度和状态，不记录用户原文。

## 验证

- 定向测试证明：cleanup 被作为可续聊的本地 AI 任务启动，首轮任务文本禁止写入，UI 使用 `/ai-runner/run-prompt` 与续聊接口而不是一次性 `/cleanup/runs`。
- 编译 TypeScript、运行整理与本地 AI 定向测试，并重新生成 Figma 插件 `code.js`（若插件源码有改动）。
